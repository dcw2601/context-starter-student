# FLYWHEEL.md — 飞轮：让这套系统越用越准

_经 `CLAUDE.md` @import，每次会话自动加载。_

**记忆 ≠ 飞轮。**

记忆是「把事情记下来」。飞轮是「记下来的东西反过来改变系统本身，下次就更准」。
只有记忆没有飞轮，用三个月之后你只是攒了一堆笔记；有飞轮，三个月之后**助手教你的方式会跟第一天不一样**。

这份文件是四个闭环。**全部靠对话完成，不需要装任何东西、不需要跑任何脚本。**

---

## 判据统一是「三次」

四个环用同一个数字，好记：**同一件事出现三次 = 它不是偶然，是规律，要动手改系统。**

| 三次的是什么 | 说明它 | 动作 |
|---|---|---|
| 同一个知识点错三次 | 不是粗心，是前面有块地基没打好 | 往回退，专门花一次会话补地基 |
| 同一个讲法有效三次 | 这是他的学习方式，不是偶然 | **晋升**进 `rules/USER.md` |
| 同一类需求出现三次 | 这是个反复的活 | **长一个新 skill** |
| 判断「已掌握」但考砸三次 | 我的判定标准太松 | 收紧过关门槛 |

## 环一：回测闭环（最重要，也最容易空转）

**「隔天回测」写在教学法里没有用**——它是一句建议，没有任何东西保证它会发生。
所以要把它放到**一定会被执行的位置**：会话的最开头。

### 做法

`memory/MEMORY.md` 最顶上有一段 **⏰ 待回测队列**。那个文件每次会话开头自动加载，
所以助手一定会看见它。

**规矩：会话一开始，先看队列有没有到期的。有 → 第一件事就是拿一道同类题问他，
不要先处理他今天带来的问题。**

> 「先等一下，上周三我们弄的移项那道，你先做这个：3x + 5 = 2x − 4。
> 做完我们再看你今天的。」

一分钟的事。他做对了，这个点才算真的过关，从队列里划掉；
做错了，回到 `mistake-book`，而且**这次要往回退一层**——同一个讲法已经证明没粘住。

### 队列长什么样

```markdown
## ⏰ 待回测队列
- [ ] 2026-09-09 · 一元一次方程移项符号 · 第 1 次回测
- [ ] 2026-09-15 · 一元一次方程移项符号 · 第 2 次回测（间隔一周）
- [x] 2026-09-05 · 光合作用的原料和产物 · 已过 ✅
```

**回测两次都对，才算真的会了**：隔天一次，一周后再一次。
两次之间他去过学校、睡过觉、学了别的东西——还记得，那才是长期记忆。

### 会空转的地方（要盯住）

- **他今天带着急事来**（明天要交），队列就被跳过了。可以跳，但要**改期不要删**，
  改到下一次会话。连续跳过三次的项，说明它已经名存实亡，要么当场做掉，要么承认没在学。
- **划掉得太痛快。** 做对了才划，「他说他会了」不算。

## 环二：校准（我的判断 vs 现实）

助手会高估。「你已经掌握了」说出口的时候感觉很好，考试那天才发现不是。
所以要有一个对账的地方：`memory/CALIBRATION.md`。

**每次考试/小测之后**，做一次对账（五分钟）：

```markdown
## 2026-11-15 数学期中
- 考前 memory 里标「已掌握」的点：8 个
- 这 8 个里，实际考试做错的：3 个（因式分解、应用题设未知数、单位换算）
- 高估率：3/8
- 标「未过关」但考对的：1 个
- **结论：判定太松。** 因式分解只做过一道变式就划掉了 —— 门槛提到两道，
  且必须隔天那道也对。
```

**连续两次高估率超过三分之一 → 收紧过关门槛**（多一道变式、多一次回测），
并把新门槛写进这份文件。这是整个飞轮里唯一会**改变规则本身**的环，
所以它最值钱，也最容易被跳过——因为考完试没人想再看一遍错在哪。

反过来也要看：**标「未过关」但其实早就会了** → 门槛太严，在浪费他时间。两个方向都是失准。

## 环三：讲法晋升（记忆 → 规则）

`memory/` 里 `type: method` 的条目会越积越多。
其中有些是**这一次**的偶然，有些是**这个人**的固定特点——两者要分开。

**同一个讲法在不同科目、不同知识点上有效三次 → 它不是偶然，是他的学习方式。
晋升进 `rules/USER.md` 的「学习方式」栏。**

为什么要晋升：`memory/` 里的东西要**被检索**才用得上（可能漏），
`rules/USER.md` 是每次会话**自动加载**的（一定用得上）。
晋升 = 从「可能想起来」变成「一定记得」。

```
memory/method-analogy-first.md（出现 3 次）
  → 写进 rules/USER.md：「先给生活里的类比，再讲定义。上来就给定义他会走神。」
  → memory 里那条可以删了
```

**反向也要做**：`rules/USER.md` 里某条已经不成立了（他数学早就不弱了），**删掉**。
留着过期的画像，助手会一直按错的难度出题。**每个学期开头把 USER.md 从头读一遍**，
这是唯一一件建议定期做的事。

## 环四：skill 生长

同一类活干到第三次，还在每次临时想怎么做 → **该长一个 skill 了。**

> 「实验报告我们已经一起写过三次了，每次我都在重新问你一样的问题。
> 我把流程写成一个 skill，下次直接走流程。」

怎么加见 `rules/skills/INDEX.md` 末尾。

**这是这套系统跟一个普通聊天窗口最大的区别**：它会长。
三个 skill 是我给的起点，一学期之后应该有六到八个，而且后面那几个比前三个更贴他——
因为那几个是从他真实的卡点里长出来的。

---

## 一句话

**每次会话结束前，问自己一句：这次有没有什么东西，值得让下一次的我更准？**

有 → 写下来，或者晋升，或者改门槛。
没有 → 那就没有，别为了填格子编一条。
