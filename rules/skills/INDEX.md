# skills/INDEX.md — 助手会做的事

真正生效的 skill 文件在 `.claude/skills/<名字>/SKILL.md`。
这份 INDEX 是给人看的目录 —— 想知道助手会什么，看这里。

| skill | 干什么 | 什么时候会自动触发 |
|---|---|---|
| `mistake-book` | 错题本：诊断错在哪一层 → 补那一层 → 变式验证 → 隔天回测 | 「这道我错了」「订正错题」「考砸了」，或贴了一张错题照片 |
| `concept-ladder` | 概念阶梯：一句话 → 类比 → 定义 → 例子 → 他自己讲一遍 | 「什么是 X」「这一章看不懂」「老师讲的没听懂」 |
| `essay-review` | 作文批改：结构 → 内容 → 语言三轮，只指问题不代写 | 「帮我看看作文」「这段怎么写」 |

**三个是起点，不是终点。** 这套系统的重点就是你可以自己往上加。

---

## 怎么加一个新 skill

比如你想要一个「考前一周复习计划」的 skill：

1. 建文件夹 `.claude/skills/exam-plan/`
2. 在里面建 `SKILL.md`，开头必须有这段 frontmatter：

```markdown
---
name: exam-plan
description: 考前复习计划——按剩余天数和薄弱点排每天的复习内容。触发：「下周考试怎么复习」「帮我排复习计划」「考前一周」。
---

# 考前复习计划

（这里写清楚具体怎么做：第一步干什么、第二步干什么、
什么情况下要停下来问、产出长什么样。）
```

3. 回来在上面的表格里加一行。

**`description` 决定这个 skill 什么时候会被自动用上**，所以要把**触发的说法写全**
—— 你平时会怎么说这件事，就写什么。写得含糊，它就不会在该出现的时候出现。

**写 skill 的要领**：写具体的动作，不要写口号。
「要有耐心」没用；「每讲完一层停下来问一句『到这儿有问题吗』」才是能执行的。

## 什么时候该加新 skill

不用刻意想。判据只有一条（`rules/FLYWHEEL.md` 环四）：

**同一类活干到第三次，还在每次临时想怎么做 → 该长一个 skill 了。**

第三次写实验报告、第三次背单词、第三次排考前计划——
如果每次助手都在重新问你一样的问题，那说明这个流程该固定下来了。

一学期下来这里应该有六到八个，而且后面长出来的几个会比前三个更贴你，
因为它们是从你真实的卡点里长出来的，不是我猜的。
