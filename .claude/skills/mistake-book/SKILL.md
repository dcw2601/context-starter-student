# 错题本

**目标不是把这道题讲对，是让他下次遇到同类题自己能做对。**

## 第一步：先看他的过程，不要先讲

**没看到他的解题过程就开讲 = 在猜。** 先要到这三样：

1. 题目原文（照片或抄写都行）
2. **他自己写的过程**（这个最关键，错误的形状全在这里）
3. 标准答案（如果有）

他只发了题目没发过程 → 先问：「你是怎么做的？把草稿发我看看，哪怕是错的。」
他说「我完全不会做，一片空白」→ 那这不是订正，是没学过，转去 `concept-ladder` 先讲概念。

## 第二步：判断错在哪一层

这是整个 skill 的核心。**不同层的错，补法完全不同，补错了等于没补。**

| 层 | 长什么样 | 怎么补 |
|---|---|---|
| **读题** | 会做，但答非所问；条件看漏了；单位没换 | 练读题：让他把题目改写成「已知…求…」 |
| **概念** | 公式记成了别的；不知道这个符号什么意思 | 回去讲概念，用 `concept-ladder` |
| **方法** | 概念清楚，但选了一条走不通的路 | 讲「什么时候用哪种方法」的判断依据 |
| **计算** | 思路全对，算错了 | 不用讲概念。看是符号、进位还是抄错，针对性练 |
| **前置知识** | 这道题需要的更早的东西他就没扎实 | **停下来往回退**，先补前面那块（见 TEACHING.md 第四节） |

判断完，**明确告诉他是哪一层**：
「你思路完全对，是第三行把负号弄丢了 —— 这是计算问题，不是你不会。」
这句话本身就有价值，因为大多数人错完只知道「我错了」，不知道错在哪一层。

## 第三步：补，但只补那一层

- 计算错 → **不要**重讲一遍概念。他会觉得你在浪费他时间，而且他确实会。
- 概念错 → 才需要回到概念。
- **一次只补一个点。** 一道题错了三处，先修最靠前的那一处，其余的下次。

用提示阶梯（`rules/TEACHING.md` 第一节），从 L1 开始，让他自己走回正确的路上。
**不要直接给出正确的完整过程。**

## 第四步：出一道变式，他独立做

改数字、改问法、改情境，考同一个点。**这一步不给任何提示。**

- 做对了 → 记「初步过关，隔天回测」。
- 又错了，而且错在同一个地方 → 说明第三步没补到位，换一个讲法再来。
- 又错了，但错在别的地方 → 那是新的一层，记下来，下次处理，**今天不追**。

## 第五步：写进 memory

在 `memory/` 里建或更新一个文件（例如 `mistakes-math.md`）：

```markdown
## 2026-09-08 一元一次方程
- 错在：移项时符号没变（计算层，不是概念层）
- 补法：让他每次移项写一步「两边同时减 3x」，不跳步 —— 这个讲法他接受了
- 变式：独立做对 1 道
- 状态：初步过关，**待隔天回测**
```

同时在 `memory/MEMORY.md` 加一行指针。

**下次会话开头，主动拿一道同类题问他** —— 这才是错题本真正起作用的地方。
只订正不回测的错题本，跟没有一样。

## 反复出现的错

同一个点在 memory 里出现三次以上 → 这不是「粗心」，是有一块地基没打好。
往回退，找到那块地基，专门花一次会话补它。
